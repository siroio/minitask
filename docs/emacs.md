# Emacsフロントエンド

`M-x minitask`でEmacs内に一覧を開きます。Emacs 27.1以降とminitask 0.6.0のCLI（JSON形式2）を使用し、追加のEmacsパッケージは不要です。Emacs 30.2 / Windowsで検証しています。

ワークスペースごとのMarkdownをTUI・LLM向けCLIと共有します。一覧と状態・日付変更にはCLIを使い、本文は通常のEmacsバッファで編集します。Evilを使っている環境でも、一覧では以下のキーをそのまま使えます。

## 起動設定

`init.el`に追加します。実行ファイルと、展開先の`emacs`ディレクトリへのパスを指定してください。以下のパスは配置した場所に置き換えます。

```elisp
(add-to-list 'load-path "C:/Tools/minitask/emacs")
(autoload 'minitask "minitask" nil t)
(setq minitask-executable "C:/Tools/minitask/minitask.exe")
```

Emacsを再起動するか、この設定を評価して`M-x minitask`を実行します。既存のキー割当は変更しません。

保存先はCLIと同じで、既定はWindowsの`%APPDATA%/minitask`です。別の保存先を使う場合は、起動前に設定します。新規の保存先はディレクトリを先に作成してください。

初回で既定の保存先がまだなければ、TUIを一度起動して終了すると用意できます。

```elisp
(setq minitask-home "D:/Tasks")
(make-directory minitask-home t) ; 新規の保存先を用意する場合
```

ワークスペースが複数あれば起動時に選択できます。まだなければ、空の一覧で`n`を押して作成します。保存先を変更して既存の一覧を開き直す場合は、古い`*minitask*`バッファを閉じてから`M-x minitask`を実行します。

## 操作

| キー | 操作 |
| --- | --- |
| `j` / `k`、上下矢印 | 項目を移動 |
| `RET` | 詳細を別ウィンドウに表示 |
| `e` | 個別Markdownを編集 |
| `a` | タスク・ノート・方針・質問・マイルストーンを追加 |
| `s` | 許可された状態へ変更 |
| `d` | 予定日・期限・マイルストーン日を編集 |
| `c` | 予定のある日を色付けしたカレンダー |
| `v` | 作業の続き・タスクすべて・各種類の一覧を切替 |
| `w` / `n` | ワークスペースを切替／作成 |
| `/` | タイトル・本文を検索。空欄で解除 |
| `g` | データと表示文言を再読み込み |
| `?` / `q` | 操作一覧／閉じる |

列の見出しをクリックすると並べ替えられます。画面幅に合わせてタイトル列の幅を調整します。詳細は別ウィンドウに表示し、Emacsのテーマに従って状態を色分けします。

Markdownは通常のファイルとして開くため、設定済みのMarkdownモードを使えます。`C-x C-s`で保存すると一覧も更新され、`C-c C-c`で保存して一覧へ戻ります。新規項目も作成直後にMarkdownが開くので、詳細をそのまま記入できます。

新規タスクの予定日・期限はどちらも今日です。カレンダーの日付一覧から追加した場合は、どちらも選択した日になります。日付は本文のMarkdown、または一覧の `d` で変更・解除できます。

## ノートの文章をタスクにする

1. minitaskのノート一覧で `e` を押し、ノートのMarkdownを開きます。
2. タスクにしたい文章を範囲選択して `C-c C-t`（`M-x minitask-region-to-task`）を実行します。
3. タイトルと完了条件を入力します。タイトルの初期値は選択範囲の先頭行です。完了条件は後から記入できます。

選択範囲全体を新規タスクの「補足」にコピーし、そのMarkdownを開きます。複数行を選んでも1つのタスクです。予定日・期限はどちらも今日になります。

元のノートの文章は残り、未保存の文章も選択できます。この操作ではノートを自動保存しません。一覧側で別のワークスペースを表示していても、元のノートと同じ保存先・ワークスペースへ作成します。範囲未選択・空白のみ・入力中のキャンセルでは作成しません。書き込みエラーの場合も元の文章を保持します。一覧を更新して作成有無を確認してから再操作してください。

タスクを完了にする場合は完了条件を確認し、検証結果を入力します。質問を回答済みにする場合は回答を入力します。これらの内容はMarkdownへ保存されます。マイルストーンには日付を指定し、完了条件は要求しません。

日付編集にはEmacs標準のOrgの日付入力を使います。ISO日付の直接入力、相対日付、カレンダー選択が可能です。設定済みのActionの日付は解除できます。カレンダー表示では`RET`で選択日のタスクとマイルストーンを表示し、`q`で戻ります。カレンダーの予定情報は`c`で開いた時点のものです。

## 保存と表示文言

TUIを開いたままでも一覧を取得できます。状態・日付・項目追加はTUIを閉じてから行ってください。外部変更を検出した場合は更新を拒否するため、`g`で読み直して内容を確認します。Emacsで対象Markdownに未保存の変更がある場合もCLI更新を拒否します。

本文の直接編集は通常のEmacsの保存処理です。他のエディタとの同時保存を避けてください。状態をCLIで変更した後も、開いていた編集バッファと保存時の一覧更新を維持します。

表示文言は [emacs/locales/ja.json](../emacs/locales/ja.json) にあります。変更後は`g`で反映できます。Rust TUIの翻訳ファイルとは別なので、Emacs側の文言を変えるためのRust再ビルドは不要です。

別の言語はJSONをコピーして値を翻訳し、`minitask-locale`と必要なら`minitask-locale-directory`を設定します。`%s`などの差し込み指定は保ってください。未指定のキーは日本語へ戻ります。保存データの管理見出し・状態値は翻訳せず、ノートの本文にも構造を強制しません。

Windows版Emacsのプロセス引数はシステムの文字コード、CLIのJSONはUTF-8で処理します。この環境のCP932で表現できない文字が引数に含まれた場合、文字化けしたデータを保存する前にエラーとして停止します。

## 検証

以下はソースコードから開発する場合の検証手順です。配布ZIPにテストコードは含まれません。

```powershell
& 'C:/Program Files/Emacs/emacs-30.2/bin/emacs.exe' -Q --batch -L emacs -l emacs/minitask-tests.el -f ert-run-tests-batch-and-exit
```

実CLIと一時保存先を使う12件のERTで、日本語の受け渡し、workspace限定、検索、タスク・ノート・マイルストーンの操作、競合・未保存の拒否、編集と保存後の更新、日付の選択と初期値、ノートの範囲選択からのタスク作成・本文保持を確認します。既存の実データは変更しません。

2026-09-09に9件のERT、警告をエラー扱いしたバイトコンパイル、端末版Emacsでの一覧・カレンダー起動、既存のEvilを読み込んだautoloadからの起動を確認しました。
